# fontc: a duplicated glyph name fails as "N jobs stuck pending"

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of
> @felipesanches, but submitted **without human review**. @felipesanches himself would
> still need to participate in the thread if he wants to contribute to the review.

**fontc**: 1.0.0 (via gftools-builder3 e851b8b), also 0.6.0.

A Glyphs source with two glyphs named `a` fails with

    Unable to proceed; 30 jobs stuck pending

and nothing that names the duplicate. Renaming the second to `a.1` builds.

`workload.rs` (`insert_with_bookkeeping`) increments `count_pending[Glyph]` once
per job, but `jobs_pending` is keyed by `Fe(Glyph(name))`, so the second `a`
replaces the first. The counter never reaches 0, `Fe(GlyphOrder)` never becomes
launchable, and everything downstream is reported stuck.

Suggest rejecting the source with an error naming the glyph.

## Reproducing

`DupName.glyphs` / `UniqueName.glyphs` (600 bytes each, identical except the name):

    fontc --build-dir build -o DupName.ttf DupName.glyphs
