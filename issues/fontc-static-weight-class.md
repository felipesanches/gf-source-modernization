# fontc: a single-master Glyphs source ignores its instance's weightClass

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of
> @felipesanches, but submitted **without human review**. @felipesanches himself would
> still need to participate in the thread if he wants to contribute to the review.

**fontc**: 1.0.0 (via gftools-builder3 e851b8b). **Reference**: fontmake 3.11.1.

A Glyphs 3 source with one master and one instance `Bold` carrying `weightClass = 700`:

| compiler | OS/2.usWeightClass |
|---|---:|
| fontmake 3.11.1 | 700 |
| fontc 1.0.0 | 400 |

`fontbe/src/os2.rs` takes usWeightClass from the `wght` axis default, else from
`static_metadata.misc.us_weight_class`, else 400. A single master has no axis, and
`glyphs2fontir` never sets `misc.us_weight_class` or `misc.us_width_class` --
`ufo2fontir` sets both from fontinfo (`source.rs:1189-1192`). So the instance's
`weightClass` is never read: `glyphs-reader` parses it, but only to map a `wght` axis.

Every static Bold, Light, etc. built from a one-master Glyphs source comes out as 400,
and `widthClass` is lost the same way.

## Reproducing

A 30-line source and a script: `tools/probes/fontc_static_weight_class/` -- `run.sh`
builds it with both compilers and prints the two values above.
