> wouldn't an easier and more general-purpose approach just be to have an operation which calls `ttx -m` to merge in a TTX dump? That could also handle MATH tables, etc.

For whole tables, yes: fpgm, prep, cvt, gasp, hdmx, LTSH and VDMX merge fine that way (as would MATH). The glyph programs are the problem: they live inside glyf, and `ttx -m` replaces whole tables. A glyf dump holding only some glyphs does not compile (KeyError on the first missing glyph), and a complete one replaces every outline with the release's, so the font would no longer be built from its source and later source edits would be silently dropped. maxp and head, which carry the hinting limits and flags, are also tables the build writes.

So what this PR does beyond copying tables is put each glyph's program on the built glyph, refusing it when the glyph's points differ from the ones the program addresses, and first make the built points match the release where the toolchain changes them (contour start points, the midpoint on-curves fontc drops, F2Dot14 transforms, stale glyph boxes). A merge cannot do either.
