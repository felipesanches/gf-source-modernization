Reworked along the lines of your comment on #131 ("setting the glyph categories should be enough"): the flag and the filter are gone, and nothing is written as feature code. The problem: an SFD gives every glyph a GDEF class, either stated (`GlyphClass:`) or, when that is absent or 0, following from the glyph: `.notdef` none, a mark if its first non-cursive anchor is a mark, a ligature if it is a ligature substitution's result, a base otherwise. The reader carried only the stated classes into categories. It now sets the category for the automatic ones too, so an anchorless base is a base and an unclassed accent with a mark anchor is a mark, whatever their names say. The SFD writer leaves a base's class unstated where FontForge would derive it, so SFD files round-trip as before. Classes no category can express are a matter for the font's own source, as you said; they are not handled here. Tests: `test_sfd_glyph_classes_are_glyph_categories`, `test_glyph_classes_survive_an_sfd_roundtrip`.
