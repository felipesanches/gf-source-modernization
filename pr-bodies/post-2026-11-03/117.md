Three more commits:

- Macintosh name records get no Name Table Entry. A Macintosh record's name is keyed by its Macintosh language code ("en" for language 0), and the language lookup matched those codes too, so a font with Macintosh records got Windows entries with a Macintosh language ID. It now looks up Windows language IDs only and skips a Macintosh language; `test_a_macintosh_name_gets_no_entry` covers it.
- KOR and MOL are Glyphs language codes, so they were added to the layout tag table: a Korean family name now stays in its localized property as KOR (`test_a_korean_family_name_stays_in_its_property`).
- The Glyphs reader now reads Name Table Entry parameters back into the names, for these entries and for #101's: `<id>; <value>` is the default record, `<id> 3 1 <language ID>; <value>` a Windows record in that language. They are read from the file's own parameter list, since a font may have several, and the single copy the loader keeps is dropped, so writing the font out again states each name once (`test_name_table_entries_survive_a_glyphs_round_trip`).
