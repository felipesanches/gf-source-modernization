Title: Harden the build workflow (zizmor)

Body:

Problem: googlefonts runs zizmor on every pull request, and it fails on this template's `build.yaml`. A repository that adopts the template in a PR gets a red mandatory check, e.g. googlefonts/abrilfatface#1: 27 findings (15 template-injection, 10 unpinned-uses, 1 excessive-permissions, 1 cache-poisoning).

This PR fixes all of them in one commit:

- Each job gets only the permissions it uses (`contents: read` for the build, `pages: write` and `id-token: write` for the deploy, `contents: write` for the release) instead of `write-all`.
- `run:` scripts read `GITHUB_REF_NAME`, `GITHUB_REPOSITORY` and `ZIP_NAME` from the environment instead of expanding `${{ }}` into the shell.
- Actions are pinned to commit hashes, with the version in a comment.
- Checkouts set `persist-credentials: false`.
- The venv cache is removed: the same workflow publishes releases, so a release must not be built from a cache another run wrote. (#225 removes it too.)

zizmor 1.32.0 now reports no findings (`zizmor --offline .github/workflows/build.yaml`). It conflicts with #225 in the cache and `ZIP_NAME` lines; I am happy to rebase onto it if that merges first.
