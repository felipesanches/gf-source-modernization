Title: infer-mark-category: leave glyphs encoded at non-mark codepoints alone

Body:

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

Problem: `--infer-mark-category` classes every uncategorised glyph whose anchors are all mark-side (`_top`, `_btm`) as a mark. In FontLab-mastered sources the spacing accents (acute, grave, cedilla, ogonek, ...) carry exactly those anchors, so that they can be placed as components, and they are encoded at U+00B4, U+0060, U+00B8, U+02DB: not marks. Classed as marks they go into GDEF class 3, the compiler zeroes their advances, and kerning and mark attachment read them as marks. Atomic Age (AtomicAge-Regular.vfb, EbenSorkin/Atomic-Age bb96b179) loses the advances of 15 such glyphs (acute 909 -> 0, dieresis 1167 -> 0, ...) and gets 27 GDEF classes the shipped font does not have.

Fix: a glyph encoded at a codepoint whose Unicode general category is not Mn, Mc or Me is left as it is, whatever its anchors. Unencoded glyphs and glyphs encoded at mark codepoints are classed as before. Uses `icu_properties` (already in the dependency graph through fontbe) for the general category, as glyphs-reader does.

Tests: the existing test is unchanged; a new one covers an encoded spacing accent (stays Unknown), an encoded combining mark (Mn) and an encoded spacing combining mark (Mc), both marks.

cargo fmt and clippy clean; `cargo test -p babelfont`: all pass but the 11 robocjk and decompose tests that need external noto-cjk-varco data.
