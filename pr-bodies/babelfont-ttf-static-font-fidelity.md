Title: ttf: read a static TrueType font so that it compiles back to what it was

Body:

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

Some families Google Fonts ships exist only as binaries: no source of them is known anywhere. Reading such a .ttf with the TTF reader, writing .glyphs and compiling it with fontc (gftools-builder) should give the font back. It did not: names, OS/2 values, kerning and some outlines came out different. Each commit fixes one way, with a test on small fixtures (`resources/ttf/make_fixtures.py` writes them with fontTools):

- **Outlines.** A component's 2x2 transform was transposed (rotated components turned the wrong way). A TrueType rasterizer draws a glyph shifted by lsb - xMin; simple glyphs were read as drawn but composites as stored, so a composite whose component has a stale lsb moved (questiondown, a mirrored question, by twice the shift); and a component flagged USE_MY_METRICS places its composite. glyf contours are clockwise and a source's counter-clockwise, so the reader now reverses them, and the compiled font gets the binary's own directions back.
- **A static font** is one master and one instance named after its style (ID 17, else 2), not a master "Default" (which compiled to subfamily "Default"); its OS/2 values are read (fsType, PANOSE, sFamilyClass, the fsSelection bits a source states, lowestRecPPEM, and for a static font usWeightClass/usWidthClass); x-height and cap height come from x and H when OS/2 is older than version 2, as the spec defines them; head.fontRevision and hhea's line gap are read.
- **Glyph classes.** Every glyph gets the category a shaper gives it (GDEF's class, or without a GDEF a nonspacing-mark codepoint is a mark and anything else a base), so fontc no longer guesses from the name (a gravecomb that GDEF calls a base became a zero-width mark); a mark with an advance is Spacing Combining. GDEF's classes are also stated in the features, because fontc writes no GDEF when nothing is a mark, ligature or anchored base.
- **Features and kerning.** A named class's code no longer carries its own brackets (it was written as `@class_0 = [[...]];`). A legacy `kern` table is read as kerning when GPOS has no kern feature, as a shaper reads it: subtables add up, and a pair with a mark in it is left out (the table is applied ignoring marks).
- **Glyph names.** A font with no names (post format 3) gets .notdef for glyph 0 and uniXXXX for encoded glyphs, changed everywhere through RenameGlyphs; names are unique, through sr-aef's `unique_glyph_names`, which the sr-aef PR that comes with this one adds (this branch includes its commits).

Measured on Google Fonts families converted from their shipped binaries, rebuilt with gftools-builder and compared with the shipped fonts (a table comparison, and shaping with HarfBuzz over every codepoint pair and the strings each feature reaches, rendering, names, line spacing, advances, GDEF): Della Respira and Oranienbaum come back identical in all of these; Averia Libre, Averia Sans Libre, Averia Serif Libre and Sansation (6 styles each) behave identically, their only table difference being that their legacy `kern` table is now a GPOS kern feature. Before these changes none of them did (for Della Respira: usWeightClass, fsType, PANOSE, names, x-height, and 88 glyphs drawn differently).

The Light styles' family name (name ID 16) also needs the Glyphs writer to name the family after ID 16 when stated, which is a separate PR.

`cargo fmt`; `cargo clippy -p babelfont --all-targets -- -D warnings` clean; `cargo test -p babelfont --lib`: 276 passed, and the 11 tests that read the external noto-cjk-varco data fail as on main.
