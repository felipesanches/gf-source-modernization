Title: ttf: read a static TrueType font so that it compiles back to what it was

Body:

Reading a static .ttf with the TTF reader, writing .glyphs and compiling that should give the font back. For fonts Google Fonts ships only as binaries it did not: names, OS/2 values, glyph classes, kerning and some outlines changed. This builds on the sr-aef PR (branch sr-aef-uncompile-fixes), whose commits it includes. One commit per fix, each tested on small fonts that resources/ttf/make_fixtures.py writes:

- Component transforms are read in OpenType order (xy and yx were swapped).
- Composites are read where a rasterizer draws them (lsb - xMin, or the USE_MY_METRICS component's shift).
- glyf contours are reversed to a source's counter-clockwise direction.
- A static font is one master and one instance named after its style (ID 17, else 2), not a master named Default.
- The OS/2 values a source states are read: fsType, PANOSE, sFamilyClass, fsSelection, lowestRecPPEM, and the weight and width classes.
- head.fontRevision is read.
- x-height and cap height come from x and H when OS/2 is older than version 2.
- hhea's line gap is read.
- vhea and vmtx are read.
- Name records that do not decode (MacJapanese) are left out instead of being read as empty.
- A named class is stored without brackets (it was written as `@c = [[...]];`).
- The mark classes the lookups name get markClass statements.
- Glyph categories follow GDEF. A font without GDEF gets none, unless it attaches marks: then the glyphs a shaper takes for marks are marks.
- GDEF's glyph classes are stated as GlyphClassDef, since a compiler writes no GDEF without marks, ligatures or anchored bases.
- A legacy kern table is read as kerning when GPOS has no kern feature, as a shaper applies it.
- Unnamed encoded glyphs are named uniXXXX or uXXXXX, wherever they are used.

Validation: 48 static families that Google Fonts ships only as binaries, converted, rebuilt with fontc and compared with the shipped fonts (tables, shaping, rendering). With this PR, #117 and the name ID 16/17 change (a separate PR), 44 come back identical; 4 differ only in a legacy kern table becoming a GPOS kern feature, and in one italic flag fontc drops.

cargo fmt and clippy clean; `cargo test -p babelfont --features ttf --lib`: 288 passed (the 11 robocjk and decompose tests need external noto-cjk-varco data).
