An SFD states no pitch; FontForge's exporter sets `post.isFixedPitch` when every glyph it writes shares one advance (the same one-width rule that already sets PANOSE proportion 9 in `--fontforge-os2-defaults`), so a monospaced FontForge binary says fixed pitch and a conversion built with fontc says 0. This adds `post_is_fixed_pitch` to `CustomOTValues`, written as the Glyphs `isFixedPitch` custom parameter (which fontc reads), UFO `postscriptIsFixedPitch` and fontir's `is_fixed_pitch`, plus an opt-in `--fontforge-fixed-pitch` filter that sets it by FontForge's rule. It is a filter rather than reader behaviour because the value is not in the source; it is decided at export.
