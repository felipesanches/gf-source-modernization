The categories are not enough when the target is a .glyphs file: Glyphs.app, glyphsLib (`_build_public_opentype_categories`) and fontc (glyphs2fontir `category_for_glyph_preliminary`) only make a glyph a Base or a Ligature if it has an attaching anchor; only Mark comes from the category alone. A release whose GDEF classes anchorless glyphs as bases or ligatures loses those classes, and a font whose GDEF has no marks loses the table.

Measured on the 28 families converted with this branch, with only the GDEF prefix call removed: 27 come back the same, Carlito does not. Its build keeps the 142 marks, but the release's 2394 bases and 112 ligatures lose their class, and some of its GSUB lookups filter on glyph class. An explicit `table GDEF { GlyphClassDef ... }`, which all three honour, keeps them.

If you prefer, this can move from the TTF reader to the Glyphs 3 writer, where the format's limit is: write a GlyphClassDef only when the font's categories include bases or ligatures without attaching anchors. That would also cover other sources, so I would measure it on the SFD conversions first.
