Title: fontforge: define a feature's own lookups after its insertion marker

Body:

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

Every converted lookup was defined as a prefix, so the lookups a compiler generates at a feature's insertion marker (mark, mkmk, abvm, blwm, kern, dist) came after all of them, unlike in the FontForge export where the anchor lookups come first. A lookup used only by one of those features is now defined inside it, after the marker; lookups shared with another feature or called by a contextual rule stay prefixes. Cardo-Regular's shaping differences against its release drop from 324 runs to 2 (stacked Hebrew marks) and Lohit-Bengali's 31 differing words to 0. This changes lookup order, so it may deserve discussion.
