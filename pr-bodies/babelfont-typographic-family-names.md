Title: Keep the typographic family and subfamily (name IDs 16/17) from SFD to Glyphs

Body:

An SFD's LangName can state a style such as Black as the Regular of a style-linked family "Overlock Black" (IDs 1/2) within the typographic family "Overlock" (IDs 16/17); the reader named the master after ID 2 and the Glyphs writer named the family after ID 1, so IDs 16/17 were lost. Now the reader names the master after ID 17 when it links to the style ID 2 states (otherwise after ID 2, and after a derived style-linked ID 2 before the weight class), and the writer uses ID 16 as the Glyphs family, so Glyphs derives IDs 1, 2, 4, 16 and 17 itself. Where Glyphs would write no IDs 16/17 (one of the four style-linked styles), a stated ID 16 or 17 that would read differently from IDs 1/2 is written as a Name Table Entry. The `familyNames` property localizes the Glyphs family, so it holds the localizations of ID 16 and none of an ID 1 that differs from it (Thabit's "Thabit-Bold" and its Arabic ID 1 would otherwise rename the family); once glyphs3-localized-name-entries is in, the localized records of such an ID 1 go out as Name Table Entries.
