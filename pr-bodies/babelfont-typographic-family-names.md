The problem: an SFD can state a style as the Regular of a style-linked family within a typographic family, for example "Overlock Black" Regular (IDs 1/2) in "Overlock" Black (IDs 16/17). The reader named the master after ID 2 and the Glyphs writer named the family after ID 1, so IDs 16/17 were lost.

Now:

- The SFD reader names the master after ID 17 when it links to the style ID 2 states.
- The Glyphs writer uses ID 16 as the Glyphs family, so Glyphs derives IDs 1, 2, 4, 16 and 17 itself.
- For the four style-linked styles, where Glyphs writes no IDs 16/17, a stated ID 16 or 17 that reads differently from IDs 1/2 is written as a Name Table Entry.

With #117, which reads Name Table Entry parameters back, these names survive a Glyphs round trip (the follow-up PR adds the test). There is a textual conflict with #117 in `customparameters.rs` (imports and adjacent additions); whichever merges second, I will push the resolution.
