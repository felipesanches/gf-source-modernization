Title: sr-aef: write aalt's lookups as rules, and make glyph names unique

Body:

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

Two ways an uncompiled feature file failed to compile again with fontc, found converting Google Fonts families that ship only as binaries (babelfont's TTF reader, which uses sr-aef for the features):

- **aalt with lookup references.** A font whose aalt feature points at its lookups (IM Fell English SC: aalt = a single and an alternate substitution) uncompiled to `feature aalt { lookup gsub_single_1; ... }`, which fea-rs rejects ("aalt can only contain feature names and single or alternate sub rules"; feaLib accepts it). The referenced lookups' single and alternate rules are now written into the aalt block, and a lookup only aalt used is no longer also written on its own, which had shifted every later lookup's index.
- **Duplicate glyph names.** A post table may name two glyphs alike (Sansation Light Italic: two `ffi`). The features named both the same, and a source with the duplicate does not build (fontc: "410 jobs stuck pending"). `unique_glyph_names()` suffixes a taken name with the first free `.1`, `.2`, ..., as fontTools does; it is public so a converter can name its glyphs the way the features do (the TTF reader PR uses it).

Tests: `resources/aalt.ttf` (from `aalt.fea`, compiled by `make_aalt.py` with feaLib) and `resources/dupnames.ttf` (`make_dupnames.py`). `cargo fmt`; `cargo clippy -p sr-aef --all-targets -- -D warnings` clean; `cargo test -p sr-aef`: 27 passed.
