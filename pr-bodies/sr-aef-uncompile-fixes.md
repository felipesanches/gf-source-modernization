Title: sr-aef: aalt rules, valid and unique glyph names, mark class anchor names

Body:

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

Features sr-aef uncompiled from some fonts did not compile again. We found them converting fonts that Google Fonts ships only as binaries with babelfont's TTF reader. One commit per fix:

- aalt may contain only single and alternate substitutions, so lookup references in it did not compile. The rules of the lookups it references are written into it instead, and a lookup nothing else uses is dropped.
- A post table may give two glyphs the same name. A repeated name now gets the first free .1, .2, ... suffix, as fontTools does. `unique_glyph_names` is public and the TTF reader names glyphs with it, so glyphs and features agree.
- Characters a feature file does not allow in a glyph name (a space, say) become _, and a name starting with a digit or a hyphen gets a leading _.
- A glyph the post table leaves unnamed is .notdef (glyph 0) or glyphNNNNN, as fontTools names it, instead of gidNNNN.
- Made-up mark class anchors were named like mark_class_1_1, which reads as a ligature component's anchor. Now mark_class_1x1.

Tests: resources/aalt.fea + aalt.ttf, dupnames.ttf, noname.ttf. cargo fmt and clippy clean; `cargo test -p sr-aef`: 30 passed.
