Two fixes to the FontForge (.sfd) reader; no new flags.

- Quoted glyph names: FontForge quotes a `StartChar:` name only when it has a character other than printable ASCII, tab, CR or LF, and writes it in its modified UTF-7 (`SFDDumpCharStartingMarker` and `SFDGetChar` in sfd.c), the encoding the reader already decodes for subtable, lookup, class and nameid strings. A quoted name is now trimmed, unquoted and decoded, so `"C+AJIA-rculo0"` followed by a space becomes `C`, U+0092, `rculo0`; an unquoted name stays literal, `+` included.
- aalt-only lookups: a lookup registered only to `aalt` already has its single and alternate substitutions inlined into the aalt feature, so it is no longer also emitted as a named feature prefix that nothing references. A lookup that a chain context calls by name keeps its definition.
