Title: vfb: write five table values as FontLab's export does

Body:

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

Problem: five OS/2, post and hhea values of a font built from a .vfb differ from what FontLab Studio 5 exported from the same file. Each was found by reading 194 shipped Google Fonts styles back against the .vfb they were generated from and counting, per candidate rule, how many releases the rule reproduces (the probe and its counts: https://github.com/felipesanches/gf-source-modernization/tree/7ab1832/tools/probes/vfb_rules). One commit per rule:

- post.underlinePosition is the top of the underline: the stored position plus half the thickness (189 of 194 releases; the stored position as is: 4).
- The PANOSE the export writes is the font-level `panose` entry (177), not the copy in the TrueType block (28), which is usually all zeros.
- OS/2 sxHeight and sCapHeight come from the last two fields of the "PostScript Info" record (152 and 166 of 193 releases with an OS/2 version 2 table); without them the compiler writes its defaults, 500 and 700.
- hhea's ascender, descender and line gap are the OS/2 typo values (178), not the hhea entries (157).
- The weight class is the font-level weight code (189; the TrueType block's weight class: 146), and the width class the block's (190). Both go on an instance named after the style, where a compiler reads them, instead of a font-level custom parameter that none does. A single-master .vfb now loads with that one instance.

Tests: each rule has a test on resources/IBMPlexSerif-Text.vfb (stored underline -97/48 -> -73; PANOSE 2,6,5,3,5,4,6,0,2,3; x-height 518, cap height 698; hhea 780/-220/300 where the hhea entries say 1025/-275/0; weight code 450 where the block says 400) plus a unit test of the record decoder.

cargo fmt and clippy clean; `cargo test -p babelfont`: all pass but the 11 robocjk and decompose tests that need external noto-cjk-varco data.
