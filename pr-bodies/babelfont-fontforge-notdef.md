When an SFD has no glyph named `.notdef`, FontForge's TrueType exporter writes its own: a hollow rectangle with stem `em/30` (a plain-number `StdVW`/`StdHW` overrides it; the usual bracketed `[85]` does not), height `min(2*em/3, ascent)` and advance `xmax + 2*stem`, or the shared advance in a fixed-pitch font, where it also replaces an empty `.notdef` of another advance. This rule is unchanged from 2008 to tag 20251009 (`dumpmissingglyph` in `tottf.c`), so binaries exported from such sources have a `.notdef` (748 units on a 2048 em) that a conversion loses and fontc then replaces with its own. This opt-in filter adds that glyph first in the glyph order, alongside the other `--fontforge-*` filters; it also moves the existing one-width rule out of the OS/2 defaults filter so both can use it.
