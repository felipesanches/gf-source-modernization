> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

The follow-up commit c4e76c20 removes the separate drop pass: a PairPos2 rule that only changes the first glyph's x-advance, in a lookup registered for `kern` alone (not right-to-left, not called by a contextual lookup), now goes into the master kerning together with the Kerns2 pairs, and every other PairPos2 rule stays in the feature code. Within one lookup only the first subtable that holds a pair applies, so a later subtable's Kerns2 or PairPos2 value for that pair is dropped. For a pair held by two different lookups the behaviour is unchanged: the kerning model holds one value, so of two Kerns2 values the later lookup's is kept, and a PairPos2 rule stays in the feature code, where it still adds to the kerning as the second OpenType lookup would.
