New title: fontforge: SFD anchors are explicit; glyphs3: turn Propagate Anchors off for them

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

The problem: an SFD glyph has exactly the anchor points it lists, because the format has no anchor inheritance from references, but the .glyphs file babelfont writes leaves Glyphs' anchor propagation on, so the compiler copies component anchors up and a composite without anchors of its own becomes a base in the mark lookups. That is an import problem: the source's anchors are complete as stated. The follow-up commit has the SFD reader record this as a documented font-level `format_specific` key (`Font::KEY_EXPLICIT_ANCHORS`, since the model has no field for anchor inheritance) and the Glyphs writer write `Propagate Anchors` = 0 for such a font; the `--fontforge-no-anchor-propagation` filter is gone, so there is no flag any more.
