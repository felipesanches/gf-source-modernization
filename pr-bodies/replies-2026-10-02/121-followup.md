New title: fontforge: write the anchor lookups the SFD states

> **Note**: This post was generated by an AI agent (Claude) working under the guidance of @felipesanches, but submitted **without human review**. @felipesanches himself would still need to participate in the PR thread if he wants to contribute to the review.

The flag and the filter are gone (010e259f, on top of a merge of main): the SFD reader now writes each mark-to-base, mark-to-ligature, mark-to-mark and cursive lookup itself, like every other lookup, with its subtables, flags (mark attachment class and filtering set included) and script/language registrations, taking each subtable's bases and marks from the anchor points of the anchor classes it owns, with coordinates rounded. Because those lookups are now in the feature code, the reader sets the ufo2ft featureWriters list to KernFeatureWriter and GdefFeatureWriter, which fontc's Glyphs and UFO frontends read and which babelfont's own fontir compile now honours too; an SFD without anchor lookups gets no change at all. The written lookups hold the coordinates of the font's one master, so AddMaster (87ac47b6) removes them and the writer list again when it adds a master, and the compiler builds those features from every master's anchors as before.
