Three opt-in filters for the OS/2 and post values FontForge's TTF exporter computes. `--fontforge-os2-defaults` fills the x-height, cap height and PANOSE the source does not state. It also computes the ten sub/superscript and strikeout values as a group when the source has no OS2SubXSize, replacing any stated without it, as FontForge does. `--fontforge-height-glyph-count-mean` fills the x-height and cap height the source does not state. `--fontforge-underline-position` converts the UnderlinePosition the source states.

- `--fontforge-underline-position`: FontForge's UnderlinePosition is the underline's centre, and post.underlinePosition is its top. The filter applies `dumppost()`'s rule up to tag 20170731: position - thickness/2 in real arithmetic, truncated towards zero. FontForge reversed the sign in commit 9f667c9c (fontforge/fontforge#3389, first in tag 20190317), so the flag is for a binary exported by an older FontForge, whatever the export date. The SFD reader parses both values as integers and drops a fractional one, which FontForge reads as a real.
- `--fontforge-os2-defaults`, sub/superscript and strikeout: when the source has no OS2SubXSize (FontForge's `subsuper_set`), all ten come from `SFDefaultOS2SubSuper` (tottf.c). The x offsets are derived from the y offsets already truncated to 16 bits. They use the italic angle as the reader holds it, rounded to a whole degree.
- `--fontforge-os2-defaults`, PANOSE: as `SFDefaultOS2Info` computes it. `OS2WeightCheck` sets byte 2 from the Weight: name and then from the FontName. "script" in the FontName (without "sans") sets byte 0 to 3. FontName width words set byte 3, and one shared advance (`CIDOneWidth`) sets it to 9.
- `--fontforge-os2-defaults`, x-height and cap height: each one the source does not state, computed as `setos2` computes it from `SFXHeight`/`SFCapHeight` (`SFStandardHeight`, splinefont.c). `setos2` writes the two only at OS/2 version 2 or later. A TrueType export gets that only from OS2Version, OS2_UseTypoMetrics or OS2_WeightWidthSlopeOnly. For a version-1 export, the filled values are FontForge's estimate, not values found in the binary.
- `--fontforge-height-glyph-count-mean`: the x-height and cap height as a FontForge built before 2012-05-14 (commit 4d34d21ef866) computed them: the sum of the distinct round or pointed tops divided by the glyph count. Run it before `--fontforge-os2-defaults`.

Not modelled, and documented in the rustdoc: a source with none of the lines that set FontForge's `pfmset` (PfmFamily, TTFWeight/PfmWeight, TTFWidth, LineGap, VLineGap). From such a source, FontForge also recomputes a stated PANOSE, sub/superscript group, x-height and cap height, and derives the weight and width classes. The filter keeps the stated values. FontForge's Font Info dialog sets `pfmset` whenever it stores any of those values, so only sources edited by hand or written by another tool are affected.
