The SFD reader ignored `sfntRevision`, so `head.fontRevision` always came from `Version`. FontForge's exporter uses `sfntRevision` when it is set and falls back to the version string only when it is not (tottf.c: `head->revision = sf->sfntRevision`), so FontForge exports `Version: 1.001` with `sfntRevision: 0x00010000` as 1.000, where babelfont compiled 1.001.

The reader now sets the version from `sfntRevision` (to the nearest thousandth, exact for any revision rounded from three decimals), in either header order. Name ID 5 still follows `Version`, and the line is written back unchanged.
