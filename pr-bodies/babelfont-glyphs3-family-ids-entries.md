Depends on #117 and on the typographic-family-names PR (branch felipesanches:typographic-family-names); the branch merges both (resolving their textual conflict in `customparameters.rs`), and only the last commit is new.

When name ID 1 differs from the typographic family, `familyNames` holds the typographic family (typographic-family-names), which the compiler writes only in the default language, so the localizations of IDs 1 and 16 were lost. Both now become Name Table Entries (#117). Example: Nanum Gothic ExtraBold (ID 1 "NanumGothicExtraBold", ID 16 "NanumGothic", both with Korean records) kept neither Korean name. `test_a_family_that_is_not_the_typographic_family_keeps_its_localizations` covers it.
