Glyphs 2 writes `unicode` as hex. When every digit is decimal (`unicode = 2013;`) the
value is unquoted, so the plist parser yields the integer 2013. `visit_u64`/`visit_i64`
formatted it back with `{:04X}` and parsed that as hex, which returns 2013 unchanged:
en dash came out as U+07DD. They now reinterpret the decimal digits as hex.

This hits U+2013/2014, U+2018/2019, U+2020-2022, U+2026, U+2030 and similar in any
Glyphs 2 source, e.g. in gftools-builder3's static builds.

Test: `test_v2_unquoted_all_digit_hex_unicode` (2013, 0041, 00C1). The four
`test_load_upgrade` failures are pre-existing: they write to `resources/upgraded/`,
which does not exist in a fresh checkout.
