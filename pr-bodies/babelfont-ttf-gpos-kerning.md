Title: ttf: read GPOS pair kerning into the master kerning when it states the same

Body:

The problem: the TTF reader reads a font's GPOS `kern` feature as feature code only, so a font converted from a binary has no master kerning, and its kerning cannot be edited as kerning (as you asked on #105 for FontForge's kerning).

Now the reader moves a `kern` lookup into the default master's kerning, and leaves it out of the features, when the kerning model states exactly what a shaper applies:

- One pair-positioning lookup that changes only the first glyph's advance, in a GPOS with no feature besides `kern`, registered for every language system, for no right-to-left script, and called by no contextual lookup. The master kerning has no script or language, so it cannot stand for a `kern` feature beside other positioning that depends on the script record a shaper picks.
- Its flag is IgnoreMarks, or 0 in a font with no mark: no glyph in GDEF class 3, or, without glyph classes, no codepoint a shaper takes for a mark (general category M, not default-ignorable). Master kerning skips marks.
- Its glyph pairs come before its class pairs, and each glyph is in one class per side. Class pairs become first/second kern groups named `@<first member>`; a glyph pair overrides its group's value, as the first subtable holding a pair does in the lookup.

Anything else stays feature code, as before. Three fixtures cover moving the kerning, a flag-0 lookup in a font whose marks have no glyph classes, and `kern` beside `cpsp`.

Tested on the 183 Google Fonts families converted from their binaries: rebuilt from the converted sources, every family shapes as it did before the change, and 79 of their 281 styles (61 families) now carry their kerning as master kerning.
